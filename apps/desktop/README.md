# Desktop development and upgrade compatibility

The desktop uses Rust/Tauri 2, the system WebView2 runtime, Solid/TypeScript and SQLite. The production target in this preview is Windows x64, Windows 10 build 19041 or later.

## Build

From the repository root, run `npm ci`, `npm run build` and `cargo test --workspace --locked`. Run the frontend tests with `node --experimental-vm-modules --test apps/desktop/src/*.test.mjs`.

For a signed installer, set `TAURI_SIGNING_PRIVATE_KEY` to a protected key path or key content, optionally set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, then run `npm run desktop:build`. `node scripts/prepare-release.mjs` assembles an allowlisted installer, signature, portable ZIP, update manifest, source link and license files. `scripts/publish-release.mjs` publishes those files and advances the fixed channel; it requires repository release permissions.

Updater signing keys are never generated by CI. The repository stores only the public key. The release workflow reads its private key from GitHub Actions Secrets. Keep this key backed up privately: existing clients trust it for future releases.

## Fixed updater channel

The installed endpoint is:

https://github.com/abnste/mewu_ai/releases/download/update-channel/preview.json

The update-channel release remains a prerelease and is excluded from GitHub's latest stable release. Each manifest names a versioned installer under its immutable version tag. A stable 1.x release advances both preview.json and latest.json, so preview clients can move to stable without reinstalling. Source branch names are not used by the installed updater or release script; changing next to master does not change the endpoint, signing key or application identity.

Use monotonically increasing SemVer versions. Signature verification binds the installer bytes and version, rejects unsigned updates, rejects downgrade offers, and restricts installer URLs to this repository. Only the first-party settings window has updater permissions. Generated HTML/SVG cannot invoke the updater.

Update checks run after startup and every six hours, using the user's proxy setting. Installation is started explicitly in About. The updater downloads first, verifies the signature, then uses the ordinary save/drain shutdown protocol. Failure before shutdown keeps the running application; failure to launch an installer after final shutdown restarts the current application. Updates do not rename or delete the user data root.

## Legacy migration

The 0.7.4 updater recognizes `MewuAI-Remake-Setup-{version}-win-x64.exe` for stable 1.x releases and invokes NSIS with `/S`. Earlier 0.7.x versions should update to 0.7.4 first. Previews are intentionally not offered to legacy stable clients.

On the first installed transition, the NSIS hook reuses the legacy current-user installation directory when it contains MewuAI.exe. The main executable keeps that filename. Successful installation replaces the obsolete Inno uninstall registration to prevent it deleting the new executable; it never deletes legacy local application data. Subsequent remake updates use the registered remake directory.

Supported Chat Completions, Responses and Messages API profiles are imported once from legacy local settings. Credentials are decoded only by the native host and saved through the normal credential store. Unsupported or interrupted profiles are recorded without repeatedly recreating deleted entries. No model request occurs during import.

Legacy conversation/history and preferences are not fully migrated. They remain in the legacy data directory; this preview does not promise full legacy feature or data parity. The installer and legacy updater compatibility are independent of that migration scope.

## Data and rollback

New data defaults to `~/.mewu`; existing remake installations retain the existing location. Settings → Data can relocate the complete data directory after saving and shutting down. Preserve both the data directory and the storage-location record before a manual downgrade. Older executables may not understand newer scene fields; never reset a database version number to force a rollback.

This preview does not automatically make a full backup before an online installer update. Back up important data before switching between legacy and preview applications. MPL-2.0 and all collected dependency/font notices are included in the downloads.
