# 2026-09-05 项目审查与优化

审查基线：`master` / `39964da`，开始工作前已 fetch，确认与 `origin/master` 无差异。实现分支：`codex/interaction-performance-review`。版本保持 0.2.3，本轮为本地开发提交，未发布、未改动用户设置和凭据。

## 判断

产品已有完整的离线捕获、原位 AI、媒体租约、隐私和发布保护，主要问题集中在覆盖层的高频操作、长期资源占用与阅读交互。优化优先处理可复现的重复工作、资源生命周期和用户被打断的操作，同时将新增职责从庞大的窗口文件拆出。

## 已落实

| 路径 | 原行为及影响 | 当前行为 |
|---|---|---|
| 流式回复 | 每个增量先通过 Progress 排进 UI 队列，再做表面合并；多次强制布局 | 后台先合并，首批立即排队，之后约每 80ms 刷新，正常布局合并处理 |
| Markdown | 为表格按钮再次解析全文；无视频动作也重建最终正文 | 同一 AST 判断表格；相同纯正文不重建；动作变更继续严格清理旧回调 |
| 连续框选 | 样式、引用、激活变化都会重新创建裁剪 | 冻结帧与裁剪矩形不变时复用同一图像 |
| 缩放选区 | 每次拖动增量都可能同步调用外进程 UIA | 连续缩放使用原生窗口边界；单击仍精确定位控件 |
| 选区生命周期 | 已删除对象持续留在 owned 集合到窗口关闭 | 保留可撤销/重做及在途操作需要的对象，历史淘汰后回收媒体资源 |
| 历史加载 | 每次唤醒从头读完整个历史文件 | 最多读取末尾 8 MiB，从完整 UTF-8 JSONL 行开始；原文件保留 |
| 长回复阅读 | 新内容刷新自动拉回末尾 | 上翻后保持阅读位置，提供“回到最新回复” |
| 视觉细节 | 12 DIP 历史入口、低对比小字号状态、取色浮窗遮正文、历史中英混排 | 带文字的 28 DIP 入口、11 DIP 状态、更深提示色；对话区隐藏取色浮窗；按语言显示历史文案 |
| 屏幕缓冲 | 编码返回的副本有清理，MemoryStream 原缓冲未主动清除 | 编码后清除原缓冲；每次编码结束补查取消，再转移所有权 |
| 整体构建 | csproj 能构建，slnx 缺少平台映射导致 AnyCPU 依赖失败 | 解决方案与全部三个项目显式映射 x64 |

## 验证证据

- 基线默认 Release 测试：736 项通过。
- 优化后默认 Release 全量测试：745 项通过、0 失败；解决方案入口同时编译主程序、测试和 ProviderSmoke，警告视为错误，最终 0 警告、0 错误。
- 新增回归覆盖：万条突发增量的合并、取消/迟到增量、渲染异常、Dispose 后已排队回调、裁剪缓存失效、Markdown 动作更新、历史引用保留、UTF-8 大历史尾部及无完整行场景。
- 万条突发增量测试只观察到 **1 次初始 Dispatcher 排队**，完整保留 10,000 个正文字符与 10,000 个思考字符。该结果为队列行为验证，不等同于实际网络吞吐或整机加速倍数。
- 真实覆盖层资源回放：60 个区域创建/删除后保留 25 个历史需要的对象；redo 分支保持资源；在途请求期间暂缓回收；历史淘汰和请求结束后对象为 0，测试视频租约为 0。
- 实际 Debug 窗口检查中英文布局、历史抽屉、上下滚动和返回最新。英文回放上翻停在第 88 项后，后续内容增长至第 119 项仍保持第 88 项的阅读位置；点击返回最新后显示末尾。输入条底边保持固定，取色卡不再遮挡正文。
- Debug 回放仅使用合成卡片和文本，不请求远程模型，不加载真实设置或磁盘历史。回放程序与输出均不进入正式包。

## 范围与后续演进

本轮没有改动 Provider 协议、录屏编码器、OCR 模型、依赖版本、发布版本或远程服务。默认测试集包含需要环境开关才真正执行的在线/设备测试，不能把默认测试全绿等同于重新验收了全部模型、麦克风、混合 DPI 硬件与远程服务。

覆盖层主体仍较大。后续可按录屏会话、标注编辑、引用管理逐步拆分，但每一步都应保留现有交互契约与实际媒体验收。长回答当前仍按批次重建 Markdown 文档；本轮消除了逐 token 调度与重复解析，尚未实现按稳定段落增量更新。尚未建立跨显卡、多屏、长时间连续使用的统一性能基线，因此不报告未经测量的 CPU、内存或 FPS 提升百分比。
