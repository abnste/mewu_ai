# 插件与宿主边界

这份清单区分已实现的机制与尚未完成的解耦。能注册 JavaScript 服务，不等于对应产品流程已接入；原生模块可启停，也不等于第三方可以替换它的实现。

## 基准

参考 DeepSeek Harness 的客户端模块、作用域服务、布局插槽与销毁机制，以及 dsh-market 自身通过布局接口提供市场界面的做法：

- [DSH 源码](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317)
- [DSH 布局扩展](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/client/ui-layout/src/client/index.ts)
- [DSH 客户端生命周期测试](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/apps/web/tests/client-plugin-live.e2e.ts)
- [dsh-market 插件界面](https://github.com/dsh-market/dsh-market/blob/ee93bb36ab6a7d514ca72bb0f090c9fb3841d42c/src/client/index.ts)

Mewu 保留 Tauri、Rust 和隔离 JavaScript 运行时，不引入 Electron。原生窗口、系统截图、输入注入、凭据、权限、事务和素材生命周期是宿主机制。九宫格、目录组织、垃圾桶规则、提示词、远端服务协议、插件专用界面和业务状态应由插件承担。

## 全部能力类别的核查

| 类别 | 当前实际边界 | 后续要求 |
| --- | --- | --- |
| 工具箱 | 旧方案的九宫格、文件夹及垃圾桶在宿主；新方案将规则和 HTML 界面放入独立包，宿主只提供对象事务、拖放来源与界面桥 | 两种独立包实装及 GUI 生命周期验收通过后才算交付 |
| Agent | 默认循环仍为原生实现；独立 Agent 服务可被角色绑定，执行链有独立授权与撤销。内置 Agent 启停不应阻断已选的独立 Agent | 默认循环不冒充第三方插件；第三方 Agent 的会话、错误、停止、流式反馈需一致 |
| 外部 Agent 接入 | 开发包 `agent-connectors` 自己实现 Codex/ACP 协议、会话与设置界面；宿主仅增加通用设置插槽、插件共享配置和受权限约束的本机 JSON 行进程 | 当前公开 1.0.3 不支持新接口；本机某平台连通不代表所有 CLI 版本或三端通过，不复制平台凭据到插件配置 |
| 记忆 | 独立 memory 服务有绑定和存储接口；内置 Hindsight 的 HTTP 协议仍在 `hindsight.rs`，工作队列直接引用它 | Hindsight 协议与配置 UI 需迁入独立适配器；保留宿主证据、事务、删除及撤权语义，不能删代码造成既有记忆不可用 |
| 模型与接入预设 | 连接模板在声明文件；凭据和标准协议传输在宿主。`models.register` 存在，但尚无完整的模型选择、请求分发与故障回退入口 | 注册不等于可直接替换连接；需补齐通用模型绑定与分发 |
| 通讯渠道 | `channels.register` 可被服务调用，但无完整的后台收发、订阅、恢复生命周期 | 需通用事件/后台作用域；不能为每种 IM 增加专用核心分支 |
| 渲染器 | 独立插件可生成隔离 HTML；`renderers.register` 没有通用对象类型选择和恢复分发 | 需类型注册、版本迁移与无插件时的只读降级；不能把“返回 HTML”称为完整对象扩展 |
| 表格工作流 | 提示词在声明包，宿主共用选区工作流；未硬编码某个表格插件 ID | 可转为普通命令插件；宿主提供选区和会话事务 |
| OCR、翻译、长截图、置顶、语音、二维码 | 原生模块通过固定贡献枚举分发到系统适配器；其中算法/系统调用可以留宿主，专用业务编排与界面目前未完全插件化 | 逐项补通用能力接口，再搬迁编排，保留已有平台功能和授权 |
| 绘制、录屏、视频裁切/GIF | 用户指定的基础能力，核心拥有绘制和录制事务、跨平台采集与编解码 | 不为拆插件而拆碎基础功能；社区插件可组合这些能力 |
| 黑板 | 原生可选模块，黑板文档与原绘制引擎共用；不是独立可执行社区插件 | 需以通用文档/场景接口承载入口和编排，不能复制一套绘制系统 |
| CLI | 本地认证、进程端点、命令目录与分发在宿主，通过原生模块开关控制；不是用户可编程 CLI 插件 | 保留可信控制入口；可扩展命令应有独立命名空间、参数契约与撤权，不开放任意 Tauri IPC |
| GitHub 市场 | 独立仓库、release ZIP、哈希、来源提交、截图和图标已有真实目录与校验；市场设置界面仍是宿主组件 | 市场 UI 自身迁往通用设置插槽前，不声称达到 dsh-market 的自托管扩展程度 |

核查对象是 GitHub 当前目录中的真实 release ZIP，逐包核对长度及 SHA-256 后读取入口；
不是仅依据本地示例或清单描述。三个已发布包没有需要为本轮 UI 重构新增的宿主 ID 分支。

| 包 | 包内负责的业务 | 宿主机制与实际限制 |
| --- | --- | --- |
| `example.region-agent` 0.1.2 | 决策提示词、动作 JSON 校验、未执行决策的纠正循环、逐步观察和结束条件 | 宿主负责授权区域、坐标、真实截图和系统输入；当前输入适配仅 Windows。系统调用失败不会由此包自动纠正，不能称为完整恢复策略 |

| `example.interactive-widget` 0.1.0 | 尺的 HTML/SVG、刻度、拖动标记、归零按钮 | 宿主只提供隔离 HTML 对象及移动/关闭；文档源能恢复，内部 JavaScript 状态不会自动保存，尚无通用对象 codec |

## 通用界面与对象接口

`ui` 服务声明 `metadata.surface = "space-overlay"`。宿主不判断插件 ID、列数、格数、文件夹或垃圾桶。每个服务有自己的客户端文档、消息端口与生命周期，多个服务可并存。

宿主创建文档前验证插件、版本、服务、当前会话及权限。文档使用独立远端 origin、沙箱 CSP 和 `MessageChannel`；客户端只能调用自己的服务，不能指定宿主 IPC、其他插件或文件路径。新一代界面替换旧代；关闭、停用、卸载、版本变化和切换会话撤销旧调用资格。

`objects.library` 保存插件自己的 JSON 状态和宿主生成的原生对象模板。单次事务提交状态、保留对象与移除对象，使用 revision 防止覆盖并发更新。插件不能提交本机路径或伪造原生模板；捕获必须消费实际用户拖入的一次来源。对象目录仅返回名称、类型和尺寸。卸载保留持久数据，以便重装恢复；关闭界面不删除数据。

对象模板计入素材保留集合。数据结构升级为 schema 11，迁移只增加对象表并保留原文档字节；
旧版本不认识这些引用，必须拒绝写入新版数据库，避免旧版清理历史时误删插件仍使用的素材。
回退旧软件应同时恢复升级前的数据备份，不能拿新数据库直接降级运行。

当前运行模型仍是每次服务调用启动独立受限 worker。客户端文档在打开期间持续存在；服务实例不是常驻后台进程。开发版已增加 `metadata.surface = "settings"` 的设置插槽，配置写入绑定当前设置文档的有效代际；尚未完成的后台订阅和第三方对象 codec 不应写成已支持。`process.rpc` 明确允许以当前用户身份运行本机程序并继承环境，不是操作系统沙箱。

客户端向画布拖出时，`mewu.drag` 接续一次真实的鼠标按下并回传客户端坐标。
宿主接管跨 iframe 的松手、Esc、关闭、失焦和超时取消，不解释目录、列表、删除或恢复规则。
画布拖入时阻止 iframe 吞掉松手事件。普通拖动画布对象不会启动全部插件，悬停具体入口才展开它。
一个插件启停或更新也不应重新挂载其他插件文档；生命周期以插件、服务和版本为键。

## 禁止回退为专用实现

- 不在宿主新增某个插件 ID、固定列数、业务操作名或文件夹规则的执行分支。
- 不能通过关闭参数验证、授权、CSP 或对象来源校验来“支持插件”。
- 新能力须由至少两个业务不同的独立包验证；模拟 IPC、真实运行时、完整桌面实测分开记录。
- 停用和卸载必须检查入口、在途请求、事件监听、临时资源与持久数据，而非只隐藏按钮。
- 所有未完成项保留在清单，不能因 SDK 有同名注册方法就标记完成。
