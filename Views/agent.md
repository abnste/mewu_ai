# 视图实现备忘

- 录制完成/暂停原位预览后，输入框恢复焦点时必须同时设置 `_selectionPromptFocus`，沿用框选后打字保护；只反复调用 Focus/Activate 会被视频悬浮收纳立刻撤销。显式新手势仍可释放保护。视频时长从播放器真实 NaturalDuration 更新，不能长期把 Stopwatch 当媒体时长。
- 覆盖层的键盘预览必须为所有 TextBoxBase（包括 MarkdownAnswerView）让行；只在子控件补 Copy CommandBinding 无法绕过窗口先吞 Ctrl+C。回答有选择复制所选，无选择复制全文，Emoji 矢量内联必须恢复 Unicode，流式/后台核验期间同样可用。

- 对话条渠道入口保持上传按钮后方的同款圆形图标按钮。点击后只展开一层可滚动模型列表，每项直接点击切换、关闭弹层并恢复输入焦点；当前项用浅色底和勾号标记，禁止弹层内再套 ComboBox。弹层打开期间保留对话条，Esc 只关闭列表，上下键/Tab 导航不能触发截图快捷键。
- 渠道列表弹层的阴影必须与内容边框分层绘制，并在 Popup 根元素四周预留透明安全边距；阴影不能挂在带圆角边框的最外层，否则 Popup 会裁掉右侧/底部阴影或让内容发虚。

- 全局截图快捷键输入框按 Delete 清空，使用 `Key.None / ModifierKeys.None` 表示未设置；只在保存成功后注销全局快捷键，恢复默认或输入有效组合键可重新启用。

- 主界面标题栏仅保留关闭叉号，不提供最小化按钮；关闭仍隐藏到托盘，真正退出使用托盘退出入口。

- 主页状态与对话路由使用相同的 WorkBuddy → Codex → Hermes → API 判断顺序，并校验后端互斥；选中 Agent 时显示其名称、所选模型和思考程度，不能读取保留的 API 模型冒充当前渠道。保存后仍由 AppHost 刷新主页。

- API、Hermes、Codex、WorkBuddy 设置页统一使用 `AiSettingsForm`：同一标题/说明、顶部操作按钮、单行状态及纵向全宽字段；不得恢复独立卡片、大标题或不同字段字号。表单显式重置正文 FontWeight，避免选中 TabItem 的半粗体继承到整页；状态全文用悬浮提示保留。

- 渠道菜单标题必须显式把 TextBlock.Foreground 绑定到 TabItem.Foreground；全局 TextBlock 样式会覆盖隐式文字的颜色继承，不能只设置父 TabItem 的灰色就声称禁用项已变灰。未适配项统一显示灰色 `#929CAF`。

- AI 设置顶部 API、Hermes、Codex、WorkBuddy 是当前对话后端的唯一单选入口，禁止恢复页内独立“启用”勾选。打开时选中已保存的后端，全新配置默认 API；统一保存时从顶部选中项生成互斥的 HermesEnabled/CodexEnabled/WorkBuddyEnabled 兼容字段。各页控件与配置草稿复用，切换不能清空其他后端的模型、密钥、人格或思考设置。OpenClaw、Claude Code 保持禁用并灰显，悬浮提示“陆续适配中”。顶部固定、内容独立滚动；标题明确显示“请选择AI渠道：”。渠道项使用有内外安全边距的 WrapPanel，窄窗口自动换行，不得裁切末项。
- WorkBuddy 页首次显示自动读取模型，重选不重复初始化，不自动提交测试消息；刷新不等同已验证登录，只有挑战回复通过才显示连接成功。渠道按“API、Hermes、Codex、WorkBuddy、OpenClaw、Claude Code”排序，已适配项必须连续在前，两个未适配项统一灰显在末尾；索引通过 `AiSettingsTabs` 常量引用，不能再在保存逻辑散落数字。主页、配置克隆、历史作用域、工具活动提示和视频完整性核验须同时接上该后端。2026-09-06 合成设置窗验证了 598/758/1100 DIP 宽度及 100%–200% 渲染比例，四页操作区对齐，草稿切换保留。
- 需要 Dispatcher 泵的独立设置页验收应创建普通 WPF Application 并加载 LightTheme，不得仅以“不调用 Run”为理由实例化产品 App：首次 Dispatcher.PushFrame 仍会触发 App.OnStartup、单实例仲裁和 Shutdown。测试 AppHost 不调用 Start，不读取/保存真实设置；本机 WorkBuddy 页实际 DetectAsync 已在这种隔离宿主下返回 15 个模型。
- Codex 页仅提供 ChatGPT Work / Codex，用户明确不要 Chat 页。首次显示时检测官方登录及真实模型目录，检测不提交 turn；模型对应思考程度动态绑定。修改其他设置时不能强迫已保存且未修改的 Codex 配置重新连接。历史使用独立 `ChatGPT Work · Codex` / 模型作用域，不混入 API 或 Hermes 历史。
- Hermes 自动连接只在首次显示其编辑页时执行，重选标签不反复连接；API 模型列表也只在首次加载编辑器时自动初始化，后续仍由配置变更/手动刷新触发。所有页面仍沿用设置窗口的凭据防捕获、统一保存与关闭取消逻辑。

- 关于页许可说明与仓库 MPL-2.0 保持一致：允许合规商用，对外分发时按协议提供受覆盖源码及修改并保留声明。不能再显示“商业产品、部署或服务必须取得作者商业授权”。

- 2026-09-05 交互性能审查：回答刷新与资源回收分别放在 `CaptureOverlayWindow.AnswerPresentation.cs` / `.ResourceLifetime.cs`。回答默认跟随末尾；用户向上滚动时保留偏移，显示向下箭头，显式返回末尾后才继续跟随。首答、最终替换和视频动作重建共用一次排队布局，不再连续强制 UpdateLayout。
- 回到最新回复按钮必须显式设置 `Margin="0" Padding="0"`，防止继承窗口通用 Button 的 2 DIP 外边距导致与滑块偏心。验收使用 InteractionHarness 的 `--verify-answer-alignment` 比较实际 Thumb 与 ArrowGlyph 中心及显隐前后的正文边界，不得仅凭整屏缩略图判断对齐。
- 回到最新回复的小箭头放在回答滚动条底端的固定槽位内，与滚动条融为一体；不得独立占一行或使用圆形大按钮。显示/隐藏只影响箭头本身，不得改变正文宽度、高度或左侧布局；滚动条始终保留底端槽位。
- 用户明确要求历史展开/收起保持原来的纯箭头；回到最新回复也只显示向下箭头，文字仅可放在 ToolTip/无障碍名称里，不得再常驻按钮文字。状态提示为 11 DIP 且保持可读对比度。历史子树被排除自动本地化，因此角色、空状态、生成状态与提示必须显式 `LocalizationService.T`，不能再中英斜杠混排。
- 对话条或选区工具条命中时不得显示实时取色浮窗，避免遮挡回答与按钮。连续缩放只使用原生窗口边界吸附，不能在每次 DragDelta 中同步扫描外进程 UIA；单击选取仍保留精确控件定位。
- `_ownedSelections` 需在历史淘汰后回收不可达对象。保留当前选区、撤销/重做双端快照、操作快照及在途请求所需资源；请求结束后补做清理。禁止一删除就释放可重做的视频租约，也不能保留所有已删除区域直到窗口退出。
- Markdown 渲染复用同一 AST 的表格存在结果，不能为“复制表格”按钮额外解析全文。只读回答关闭编辑撤销；纯正文相同且没有动作时不重建文档；正文增量保留稳定段落，只重建变化后缀。动作更新必须移除旧按钮/回调并重新绑定，不能把 FlowDocument 对象身份当作清理是否成功的判断。
- `tests/InteractionHarness` 是合成内容 Debug 回放，中文/英文均支持；`--verify-lifetime` 在真实覆盖层对象上验证历史保留、redo、在途请求保护与租约释放。不得将回放内容或 QA 开关加入 Release 运行路径。

- 连接测试的成功、失败与取消结果统一使用 owned `MewuDialogWindow`，不得恢复系统 MessageBox；请求参数 JSON 的示例、允许字段与优先服务收费说明放入标题右侧小问号的上方悬浮提示，不再常驻占据设置页高度。
- 贴图再次截图必须合成整个透明根容器（图片、边框与阴影），不能只补回原图；快照使用完整 HWND 物理边界，按图片、像素尺寸和 DIP 尺寸缓存，旋转/缩放/跨 DPI 后重新生成。窗口透明度由合成端只应用一次，防捕获仍保持开启。

- 应用界面语言按 Windows `CurrentUICulture` 自动选择：所有 `zh-*` 使用简体中文，英语及暂未提供翻译的其他系统语言统一回退自然英语；不得恢复中英斜杠混排。代码动态创建的 WPF 控件必须进入 `LocalizationService` 的 Loaded/属性变更观察链，截图/OCR/译文、AI 回答、历史、文件名和引用标签等用户内容子树必须显式排除。Debug 视觉验收可用 `MEWU_QA_UI_CULTURE`，Release 必须编译掉该覆盖；Inno Setup 同样按系统 UI 语言自动选择英文或简体中文产品名和安装文案。
- `AllowsTransparency=True` 的自绘圆角窗口不使用系统 DWM 阴影。主界面的柔和窗口阴影必须由圆角、无命中的独立同级 `Border` 绘制，内容 `Shell` 单独做圆角裁剪；严禁把 `DropShadowEffect` 重新挂到带 `Clip` 的 `Shell` 上，否则阴影会被裁掉，整个内容子树的 ClearType 也会失效。
- 透明窗口外框要为模糊阴影预留足够的透明边距，并同步增加窗口 `Width`/`Height` 与最小尺寸，保持实际内容壳尺寸不变；否则阴影会再次被 HWND 边界截断。
- 设置窗口必须保持 `AllowsTransparency=False`，通过 `WindowChrome` 保留系统缩放边框，并用 DWM `DWMWA_WINDOW_CORNER_PREFERENCE` 请求 Windows 11 原生圆角和阴影；不得恢复整窗 `DropShadowEffect` 或透明阴影边距。
- 每次新建并打开设置窗口，在首次 ContentRendered 后自动异步检查一次官方更新；自动检查与关于页手动检查共用单个在途请求。发现新版先用 owned 喵呜浅色弹窗询问是否下载，稍后不下载；下载校验后再询问安装并重启。最新版和失败仅更新关于页状态，关闭窗口必须取消请求并拒绝迟到弹窗、下载及安装。
- 关于页的手动更新入口只读取官方 GitHub `abnste/mewu_ai` 最新正式 Release；必须严格匹配版本化安装包并优先校验 GitHub 资产 digest；只有 digest 缺失时兼容 `SHA256SUMS.txt`。有界下载并在启动安装器前再次校验 SHA-256。静默安装完成后由 Inno Setup 重启应用；下载、校验或启动任一失败时保留当前版本运行并给出可操作提示。
- 截图覆盖层无法使用普通 HWND 阴影；底部对话条必须由无命中的独立双层阴影与裁剪内容卡组成，定位、收纳、透明度和显隐统一作用于 `PromptBarHost`，内容测量仍以 `PromptBar` 为准。
- 截图覆盖层的对话条命中优先于下层选区：鼠标位于回答、思考、Hermes 进度或交互卡时不得因下层选区命中而收纳；覆盖显示器绝大部分的显式选区也不能让“进入选区收纳”永久成立。
- 鼠标进入选区工具栏及其与选区之间的过渡带时，必须保持对话条收纳并冻结工具栏当前上下位置；不得让对话条显隐反过来触发工具栏在选区上下跳动。
- 选区工具栏和标注工具栏定位固定为“上方优先”：只要选区上方容得下就始终显示在上方；仅在上方不足且下方完整容得下、同时不与对话条相交时放到下方。对话条收纳、展开和透明度动画不得参与工具栏上下方选择。
- 框选后的选区主工具栏按“区域管理 → 内容处理 → 捕获扩展 → 输出”稳定排序：引用/新增/删除，标注/OCR/翻译/表格，长截图/录屏/视频播放，复制/保存/贴图。各组以细分隔线区分并保持单行纯图标；这套排序只适用于选区主工具栏，不得误改标注绘制工具栏。
- 对话条因鼠标进入截图区域而开始收纳后，命中判断必须忽略对话条收纳前的旧占位矩形，直到鼠标真正离开截图区域；否则旧矩形会让对话条反复出现和消失。
- 全屏或近全屏显式选区同样必须在鼠标离开对话条后自动收纳；因为这类选区不存在可用于重新展开的“选区外”空间，收纳状态下只允许对话条动画前的稳定边界作为主动展开热区。局部选区仍必须忽略旧占位矩形，不能因此恢复循环闪现。
- 原位标注的当前颜色必须统一作用于画笔、高亮笔、矩形、椭圆、箭头、文字和实心序号；RGB 自定义色使用 Windows 原生完整颜色选择器。文本框枚举本机系统字体并支持字号和荧光底色；序号按区域从 1 自动递增；椭圆按 Shift 约束为不越过选区边界的正圆。文字和序号必须进入截图快照、导出以及标注模式内的撤销/重做链。
- 原位标注的橡皮擦必须统一命中 Stroke 与非 Stroke 对象，能够擦除笔迹、矩形、椭圆、箭头、文字、序号和马赛克；选择工具支持单对象选中、在选区边界内拖动及 Delete 删除。移动、擦除和删除必须同步 `DrawingElements`/`Strokes` 与撤销重做动作，不能只修改可见控件导致复制、贴图或导出仍残留旧标注。
- 选择标注后必须显式把键盘焦点交给当前 `InkCanvas`，确保 Delete 经覆盖层预览路由删除所选对象；橡皮擦单个命中点只删除视觉最上层的一个对象，连续拖动按有限距离采样，不能把重叠标注一次清空。文字工具点击已有文字、或选择工具双击文字时必须重新进入原文本框编辑。标注工具条默认只显示常用图标，字体、字号与文字荧光选项仅在文字工具激活时展开并重新定位工具条。
- 多个截图对象同时存在时，鼠标悬浮到哪个显式对象就激活哪个对象并显示其工具栏；重叠区域按视觉层级选择最上层对象，隐式全屏区域不得参与悬浮切换。
- 发送目标必须先按输入来源归一化：只保留用户显式选择的截图/录屏和上传附件，绝不因只输入文字而创建隐式全屏占位；无视觉附件时走纯文字请求，Hermes 仍沿用同一 Profile 的持续上下文。上传文件仍按实际发送顺序加入引用清单，且没有覆盖层选区的文件批注只能安全丢弃，不能映射到别的截图。
- 截图区域不显示视觉数字序号；内部仍保留稳定句柄、附件顺序和 `@图片N` 引用所需的映射，不能为了隐藏标签而删除这些内部绑定。
- 产品不提供独立文字问答窗口；文字 AI 只能在截图覆盖层内工作，允许无视觉附件的纯文字轮次。
- 独立文字问答已移除，不得恢复主界面或托盘中的“快速提问/文字问答”按钮；覆盖层回答仍可使用同一套 Markdown 渲染。
- 对话条显隐动画必须从当前有效位移和透明度继续，恢复时以约 230ms 从屏幕下方向上做线性滑入并渐显；首次唤醒也必须先在屏幕外完成布局再播放同一入场动画。动画期间的 `SizeChanged`、悬浮对象切换和定位钳制只能移动宿主，严禁取消显隐动画或直接写入可见终态；动画使用 `FillBehavior.Stop` 且目标值写入基础属性，避免 `HoldEnd` 残留导致闪现。
- 对话条回答区的最大高度必须按显示器可用高度计算，不能把当前 `DesiredSize` 再反馈成下一轮上限，否则多次测量会把回答区越压越小。回答展开时输入区底边保持锚定，内容只向上扩展。
- 屏幕结构化回答必须兼容完整 JSON 代码块及 ` ```json{...}` 同行围栏，但最终 UI 只能显示根 `answer`，不得泄漏围栏、协议字段或原始批注 JSON。
- 屏幕请求明确要求结构化回答时，疑似 JSON/JSON 围栏却缺少字符串根 `answer`、根类型错误或内容损坏且无法安全恢复，应按无有效正文失败处理，严禁把原始协议 JSON 当成普通回答显示；MiniMax M3 请求需显式使用 `reasoning_split=true` 与 `thinking.adaptive`，首个思考增量必须立即展开显示，不能等待正文到达。
- 退出手动标注时为提交文字框可以先清理键盘焦点，但必须立即把焦点恢复到可聚焦的覆盖层根画布；同时按 `IsMouseCaptureWithin` 释放 InkCanvas 子树捕获。否则完成任意标注后后续 Esc 可能没有路由目标，形状绘制中断时也可能让覆盖层表现为卡死。
- Hermes 的“Agent / 人格”选择必须使用网关 `profiles.list` 返回的真实 Profile；模型枚举、会话创建/恢复和 TTS 都要携带同一 `profile`。不同 Profile 各自保留独立持续会话，严禁为了切人格写 `SOUL.md`、切换 Hermes 全局默认 Profile 或重启用户现有网关。
- 截图覆盖层与其视觉附件引用中的 AI 正文统一渲染为原生 WPF `FlowDocument` Markdown，并保持文字可选择、可复制。Markdown HTML 只能按普通文字显示，远程图片不得自动加载，链接只允许用户主动打开 `http/https`；emoji 必须经 Emoji.Wpf 转成 Segoe UI Emoji 的彩色矢量层，不能退化成 WPF 默认黑白字形，复制时仍须还原原 Unicode；流式回答必须节流，不能每个 token 都重建文档。
- 覆盖层撤销/重做按鼠标所在区域分流：鼠标位于显式截图区域时，`Ctrl+Z`、`Ctrl+Shift+Z`/`Ctrl+Y` 操作截图历史，即使输入框仍保有键盘焦点；只有鼠标位于底部对话条且可编辑输入框有焦点时，才交给 WPF 文本框自身处理文字撤销/重做。OCR、翻译、AI 识图、区域新建/删除/移动/缩放都必须进入有限截图历史，撤销期间不得提前释放可重做区域持有的视频或 OCR 资源。
- 截图覆盖层的 AI 请求失败必须写入 `PrivacyLogger`，并按 Provider 请求阶段与回答渲染阶段区分组件名；日志只记录脱敏异常，不得记录 prompt、answer 或附件内容。OCR/翻译异常同样必须落脱敏日志。
- 贴图窗口双击必须直接关闭贴图（不是只把 `Topmost` 改为 `false`）；贴视频仍按既有产品行为取消置顶。单击按下时不得立即调用 `DragMove` 打断双击计数，只有鼠标移动超过 WPF 系统拖动阈值后，才按 `PointToScreen` 的物理像素增量用 `SetWindowPos` 移动，保持多屏与混合 DPI 正确。右键菜单的“置顶/取消置顶”文字必须与实际 `Topmost` 状态同步。
- 贴图/贴视频首次显示、回到原位和原生定位必须携带 `SWP_NOACTIVATE`，不能抢走截图覆盖层的键盘路由；贴出后覆盖层先恢复激活与根画布焦点，再以不激活方式抬高贴图。用户后来点击激活贴图时，贴图收到 Esc 必须转交当前覆盖层并沿用其取消/退出优先级，普通截图状态下关闭覆盖层但保留贴图。
- 对已有标注的区域执行贴图时，图片必须一次性扁平化当前 AI 标注、手工标注、文字、马赛克和译文后再创建贴图；视频必须先从源 MP4 生成受租约保护的临时带标注副本，再交给贴视频窗口播放。贴图和贴视频均不得修改源图片/源 MP4，关闭窗口后临时视频才允许进入后续清理。
- 上传图片的引用标签与 `@` 候选项可作为 WPF 原生拖放源；拖到透明覆盖层后应按落点所在显示器的物理工作区生成贴图，保持比例并限制初始尺寸。贴图注册后必须刷新冻结桌面把受防捕获保护的贴图合成进截图背景，同时把真实贴图 HWND 明确保持在截图覆盖层上方，便于直接拖动和双击关闭；从贴图外开始的框选仍可通过冻结背景再次截取贴图。文本和视频附件不得伪装成图片贴图。
- AI 视频时间轴批注必须留在原录屏选区：单点事件 seek 到目标时刻、暂停并显示框；动作过程从起点播放到终点，按当前帧时间在关键帧间线性插值跟踪框并在终点自动暂停。新请求、手工播放、删除区域、撤销重做和关闭覆盖层都必须取消旧的区间控制并拒绝迟到帧更新。
- 视频播放/暂停按钮只能改变播放器状态，禁止清空时间轴批注。所有播放路径都由实际呈现帧事件刷新标注；暂停后保留最后呈现帧上的标注，后续回答跳转使用 seek 后真正显示出来的帧时间。单点标记允许一个不超过 120ms 的现场帧容差以覆盖帧率取整，但 PNG/GIF/MP4 导出仍严格按协议时间，不得扩大标注时段。
- 流式思考区每次渲染增量及最终内容替换后都必须滚动到底部；空正文或请求异常不得回滚并抹掉已经显示的思考/回答层，应停止思考动画、保留可展开的思考内容并显示明确失败卡，同时禁止写入历史和批注。
- 视频理解提示应默认要求关键事件/可定位目标的时间轴批注；解析允许首尾关键帧位于区间端点以内，不要求严格等于 `startTime/endTime`。模型未返回有效视频批注时必须明确提示“没有时间轴标注”，不能显示完整成功。
- 所有首轮视频回答都应在同一请求所有权和附件租约内做至多一次独立完整性核验，不能只在批注数为零时补标；核验需覆盖原问题中的每个独立对象/片段并校正为目标稳定出现的时间，只有有效批注数不少于初稿时才替换。成功批注需在 Markdown 回答末尾生成本地可点击“跳到/播放”链接，链接直接驱动原位视频 seek 或区间跟踪，不得伪装成外部 URL、打开浏览器或新窗口。撤销重做恢复回答时也要按快照批注重建链接。
- 有效视频批注落地后按全部关键帧的最早时间自动跳转、暂停并渲染第一处标记；多个独立固定事件分别生成跳转链接，单个动作区间只生成一条“播放区间”链接，不能再把起点和终点伪装成两个重复事件。跳转链接只 seek 后暂停，播放链接才启动区间跟踪。
- 视频初稿的批注映射与画布应用必须先于完整性核验：初稿一到立即原位画框、跳到首标记并生成链接。核验应先在内存中映射，只有有效批注数不少于初稿才整体替换；核验取消、异常或较差结果必须保留初稿。单视频可容错重映射错误 `regionIndex`，多附件不得放宽。
- 保存截图或录屏时仅在确有 AI/手工标注时询问是否包含标注；选择“否”必须重新从干净截图帧或源 MP4 导出，不能复用默认带手绘的预览图。录屏对象同样允许进入原位绘图模式，手工层作为全时段静态覆盖，AI 层按批注时间动态合成。
- 保存图片必须在打开系统文件选择窗口之前完成最终像素冻结与标注扁平化；文件窗口拥有焦点及关闭后的 owner 激活阶段不得刷新桌面帧，避免把“另存为”界面写入当前或后续截图。截图默认名为 `截图_yyyyMMdd_HHmmss`，视频默认名为 `录屏_yyyyMMdd_HHmmss`，贴图/贴视频保存保持同一命名规则。
- 覆盖层的保存选择与 RGB 调色使用自有圆角模态窗，不能露出 Windows/WinForms 默认控件风格；模态窗必须是覆盖层的 owned window、启用防捕获并保持当前标注会话。字体下拉从 WPF `FamilyNames` 选取当前中文语言名称，内部仍使用字体 `Source`。颜色选择修改文字前景色，荧光底色固定为黄色且与文字颜色互不覆盖。
- 回答中的视频动作以 `BlockUIContainer` 内的圆角按钮气泡呈现；同一正文再次设置动作时必须从 Markdown 原文重建整个文档，禁止向旧文档追加导致重复和陈旧回调。每个按钮事件显式捕获当前动作副本，确保第二个及后续定位能独立 seek。
- 覆盖层 AI 控件按后端能力分别显隐：无可用对话后端时整个 `PromptBarHost` 与区域引用按钮保持折叠；原位翻译只在远程 Provider 配置和凭据可用时显示，不能因为仅有 Hermes 而露出不可用的翻译按钮。
- 翻译图层在复制、贴图和带标注图片保存时必须按区域物理像素扁平化，且位于手工标注之上、AI 标注之下；选择保存干净原件时必须排除译文。
- 原位译文不得继续使用 OCR 原行宽度的纯色文本框或可见边框。应按原文字号测量译文并在选区内向左右扩展，只有超过整个选区可用宽度时才显式换行且不得丢字；背景从干净截图的实际覆盖区域扩边取样，使用高斯模糊与局部平均色轻度融合，文字颜色按背景亮度自适应。翻译完成后必须复用 OCR 的透明跨行选择层，支持直接拖选、`Ctrl+C` 和右键复制全部译文，撤销重做后同样恢复。
- 原位译文字形必须使用真实几何描边：浅色背景采用黑字白描边，深色背景采用白字黑描边；不得用多份偏移文字或阴影伪造。描边必须先绘制，再用完整字形填充覆盖描边的内半部分，使可见轮廓只留在字形外侧，不能侵占字芯。字形填充与描边均必须进入现场显示及复制、贴图、保存的扁平化结果，透明文字选择层继续独立负责拖选和复制。
- 自动框选预览位于选区层之上但不得命中鼠标；单击接受预选窗口，拖动越过系统阈值则进入普通框选。句柄吸附只改变对应边，不能跳动对边或生成小于最小尺寸的区域。
- 智能句柄吸附的 UI Automation 探测必须保持单个有界在途任务，鼠标移动只更新待探测坐标，不能在每个 MouseMove 中取消并重启探测；探测完成后再处理最新坐标，旧预览必须先隐藏，避免持续移动时吸附永远没有结果。
- 句柄吸附实现采用两阶段命中：Win32 `WindowFromPoint`/有序窗口枚举先给出即时预选，随后只对当前窗口做 `AutomationElement.FromPoint` 父链和鼠标点所在的有界空间分支复核；禁止恢复全窗口 UIA 深度扫描。预选和精确目标使用短期有界缓存，按下时必须同步完成一次精确探测后再锁定，避免移动到按钮时仍误选整个窗口。
- 截图吸附不能因 Chromium/Electron 的原生渲染宿主 HWND 略小于根窗口就跳过 UIA 空间分支复核；无论快速命中根窗口还是宿主子 HWND，最终都必须从该窗口根做一次有界 UIA 命中，优先返回真实 Button/Edit/MenuItem 等控件边界。
- Codex 等 WebView/Electron 的可访问树常在 Region/Group/Document 后才出现按钮，且同一点可能同时落在禁用占位 Pane、透明容器和真实内容 Region 内；截图吸附必须先从鼠标下最深的原生宿主 HWND 进入与 computer-use 一致的 UIA `ControlViewWalker`，再回退顶层窗口和 `RawViewWalker`。空间复核最多并行保留 6 条包含鼠标点的分支、24 层、每层 512 个兄弟候选，并以 120ms 单次时限硬截断；禁止扩展成无界全树扫描。
- 覆盖层遮挡时，`AutomationElement.FromPoint` 会命中自身，不能作为下层应用根的唯一入口；必须从桌面 UIA 的直接顶层子窗口按真实 HWND 获取 Provider 根并回退 `FromHandle`。全屏/近全屏应用在语义控件暂不可得时仍须回退为整窗预选，不能表现为没有任何吸附。
- 顶层窗口枚举必须排除 DWM cloaked 窗口；Windows `ClickToDo` 的隐藏全屏 `IslandWindow` 会同时满足 `IsWindowVisible` 与全屏包含关系，但并非用户实际看到的窗口。悬浮精确吸附严禁通过反复隐藏、降层或调整覆盖层 Z 顺序实现，否则鼠标移动会造成整屏闪烁并破坏贴图层级。
- Windows 主/副任务栏是智能框选的终止区域；全屏覆盖层遮挡任务栏时必须通过有界顶层窗口枚举识别 `Shell_TrayWnd` / `Shell_SecondaryTrayWnd`，进入后立即清空原生与 UIA 命中缓存并隐藏预选框，严禁穿透到任务栏后的最大化窗口形成粘住全屏的假吸附。
- 智能框选命中同一按钮时必须优先稳定的可操作父控件，不能让更小的可聚焦文字/Custom 子元素覆盖 Button/Edit/MenuItem；精确按钮已确认后，只要指针仍在其完整边界内，即时 Win32 整窗回退不得覆盖该预选框，后台 UIA 仍需继续有界复核界面变化。
- 贴图旋转后应围绕当前内容重算窗口尺寸并保持长宽比，超高的长截图按工作区高度缩小宽度而非纵向压扁；右键复制和保存始终使用当前旋转方向。
- 长截图必须在同一覆盖层原位进入交互采集：冻结桌面和遮罩对当前选区挖出透明实时区域，由覆盖层接收用户滚轮并按原始方向/增量转发给下层滚动目标，滚动稳定后才采集一帧。拼接位移必须保留正负方向：向下滚动在底部追加，向上滚动在顶部追加，反向滚回已覆盖范围不得重复增长。已接受帧在选区侧边以底部锚定、向上增长的预览连续显示；完成后结果写回原 `SelectionItem`，按原始像素宽高比在显示器内同时缩放宽高，严禁用 `Stretch.Fill` 把长图纵向压扁。结果继续支持引用、标注、复制、保存和贴图，不能直接弹出置顶窗冒充完成。采样仍限制 24 段和总像素预算，Esc/取消必须恢复原冻结选区且不丢失已有标注。
- 长截图不能只向下层 HWND 投递 `WM_MOUSEWHEEL`，Chromium、WebView 与部分 WinUI 滚动面可能忽略这种伪造窗口消息。指针在实时选区且不在控制条时持续启用 `WS_EX_TRANSPARENT`，并且仅在前台仍属于覆盖层时把焦点交给已命中的底层窗口；WPF 等窗口即使鼠标穿透也可能忽略非活动窗口滚轮。不得抢夺用户主动切换到的其他窗口焦点。第一格覆盖层收到的滚轮用带本进程标记的 `SendInput` 补发；只读 `WH_MOUSE_LL` 仅忽略这个标记，不能忽略触摸板、辅助工具或远程输入产生的其他注入事件，且始终继续输入链。会话期间注册临时 Esc 热键，使底层有焦点时仍能取消；结束、失败及关闭必须注销热键、卸载监听、恢复鼠标样式和覆盖层焦点，恢复样式失败则安全关闭。
- 长截图采集与匹配必须分离：50ms 采集轮询把冻结帧、当时指针屏蔽区和方向放入最多 8 帧、1600 万像素的 FIFO，由单一消费者后台匹配；匹配繁忙不能阻止获取中间帧，连续滚轮也不能取消在途匹配。缓冲满时提示放慢，不可无限堆积。严禁恢复 500ms 轮询叠加 280ms 防抖。只捕获当前物理像素选区，不能每帧重拍整个虚拟桌面再裁剪。位移搜索先在稀疏网格逐像素筛选，再对最佳候选密集核验；除边缘外必须保留 RGB/色度特征，避免同布局不同颜色的卡片被错配。当前匹配必须在取消和会话身份校验后，将帧、位移和合成图一起提交，提交前检查保留帧与输出像素预算；高误差时在可见控制条提示回滚找接点，保留已有长图。完成时停止入队并有界等待排空，超时允许重试而非静默丢失尾帧；取消清空队列且旧会话不得提交。验收窗口位于 `tests/ScrollCaptureHarness`，应覆盖单格、快速三格、反向滚动及底层焦点下的 Esc。
- 长截图完成或取消后，图片区域的长截图与区域录屏按钮都必须恢复显示和命中；完成后的长图允许再次进入长截图采集，取消再次采集时必须保留上一次长图结果，不能因 `CapturedImageOverride` 非空而静默隐藏或拒绝按钮。
- 长截图属于真实像素导出，禁止沿用 Debug 视觉验收的防捕获豁免。开始时必须强制启用并读回 `WDA_EXCLUDEFROMCAPTURE`，首帧及后续帧采集入口再次校验真实窗口状态；否则禁止采集，不能把蓝色选区框、光晕或预览反复拼进成品。Debug 仅在采集结束后恢复原先的界面观察模式，Release 不含恢复豁免分支。视觉验收必须检查最终导出 PNG 的接缝与边缘，尺寸正确不等于图像干净。
- AI 表格识别只发送当前显式图片选区，回答仅保留一个或多个 Markdown 表格且不得改动已有标注。检测到表格后回答标题区显示“复制表格”；一次复制必须通过同一 Windows `DataObject` 同时提供 CF_HTML 表格、CSV、Markdown Unicode 文本、位图和持久暂存 PNG 的 FileDrop，使 Excel、普通文本框、图片编辑器和桌面分别选择各自支持的格式。CF_HTML 偏移必须按 UTF-8 字节计算，表格解析使用 Markdig AST，不得用正则硬拆单元格。
- 多附件识图不能把界面显示的 `@图片N` / `@视频N` 直接当作 `regionIndex`：每个选区需持有不可变 `referenceHandle`，请求清单显式绑定显示标签、实际附件顺序、句柄、像素尺寸和归一化四角坐标。模型批注同时返回序号与句柄；句柄优先纠正冲突序号，未知句柄必须拒绝，不能回退后把框画到别的附件。输入框键入 `@` 应列出当前显式图片和视频，并把选择绑定到实际选区对象。
- 截图覆盖层的实时取色必须直接读取冻结桌面的物理像素，显示 `#RRGGBB` 色值、颜色预览和虚拟桌面物理坐标；多屏左侧/上方显示器允许负坐标。提示卡跟随指针并在四边做有限翻转和钳制，不能超出覆盖层，也不能进入截图导出内容。

- AI 图片批注先以模型粗框中心命中下层窗口的 UI Automation 元素；命中到可用原生控件时，必须直接换算其真实物理边界并跳过图像贴边，从而与 computer-use 的 accessibility-first 定位一致。控件外的图片、画布或 UIA 不可用时，才保留图像边缘微调；每轮最多处理 12 个候选，避免阻塞覆盖层。
- AI 图片批注的无障碍修正只接受 Button/Edit/MenuItem/Image/ListItem 等真实可操作语义控件；原生整窗、渲染宿主或通用容器回退不得改写模型框。语义控件仍必须覆盖或紧邻模型粗框中心且尺寸与粗框保持保守比例，严禁把局部标记扩成整个选区后被选区外框遮住。结构化结果提取出纯正文后不得再次解析正文并清空已经验证的批注列表。
- 图片与视频 AI 标注统一使用版本化 `mewu.visual-annotations/1` 协议，以不可变 `referenceHandle` 和完整附件 `regionIndex` 绑定目标，空间统一为附件内 0–1 坐标，视频额外使用秒级时间轴关键帧。同一协议支持 callout、画笔、高亮、矩形、椭圆、箭头、文字、序号和马赛克；旧扁平框协议只作为读取兼容，新请求不得继续生成旧协议。
- AI 批注映射在句柄/附件校验后统一执行“可访问性控件对齐 → OCR 行框校准 → 保守图像边缘贴合 → 质量门禁与 IoU 去重”。图片中高度重叠的说明框与矩形/椭圆只保留语义更完整的说明框；视频按时间重叠和插值框 IoU 做时空去重，只删除可由线性插值精确恢复的冗余关键帧。单次最多展示 12 个说明气泡，时间轴最多 128 个关键帧，避免模型异常输出拖垮覆盖层。

- 多个说明气泡必须先收集全部目标框，再通过同一全局布局规划器统一避让；无法全部避开时优先允许气泡之间局部重叠，也不能遮住语义目标。用户拖动后的归一化气泡位置必须同时用于现场显示、PNG、GIF 与 MP4 导出，连接线在每种输出中重新指向当前目标。
