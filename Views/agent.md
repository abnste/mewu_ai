# 视图实现备忘

- `AllowsTransparency=True` 的自绘圆角窗口不使用系统 DWM 阴影。主界面的柔和窗口阴影必须由圆角、无命中的独立同级 `Border` 绘制，内容 `Shell` 单独做圆角裁剪；严禁把 `DropShadowEffect` 重新挂到带 `Clip` 的 `Shell` 上，否则阴影会被裁掉，整个内容子树的 ClearType 也会失效。
- 透明窗口外框要为模糊阴影预留足够的透明边距，并同步增加窗口 `Width`/`Height` 与最小尺寸，保持实际内容壳尺寸不变；否则阴影会再次被 HWND 边界截断。
- 设置窗口必须保持 `AllowsTransparency=False`，通过 `WindowChrome` 保留系统缩放边框，并用 DWM `DWMWA_WINDOW_CORNER_PREFERENCE` 请求 Windows 11 原生圆角和阴影；不得恢复整窗 `DropShadowEffect` 或透明阴影边距。
- 关于页的手动更新入口只读取官方 GitHub `abnste/mewu_ai` 最新正式 Release；必须严格匹配版本化安装包和 `SHA256SUMS.txt`，有界下载并在启动安装器前再次校验 SHA-256。静默安装完成后由 Inno Setup 重启应用；下载、校验或启动任一失败时保留当前版本运行并给出可操作提示。
- 截图覆盖层无法使用普通 HWND 阴影；底部对话条必须由无命中的独立双层阴影与裁剪内容卡组成，定位、收纳、透明度和显隐统一作用于 `PromptBarHost`，内容测量仍以 `PromptBar` 为准。
- 截图覆盖层的对话条命中优先于下层选区：鼠标位于回答、思考、Hermes 进度或交互卡时不得因下层选区命中而收纳；覆盖显示器绝大部分的显式选区也不能让“进入选区收纳”永久成立。
- 鼠标进入选区工具栏及其与选区之间的过渡带时，必须保持对话条收纳并冻结工具栏当前上下位置；不得让对话条显隐反过来触发工具栏在选区上下跳动。
- 选区工具栏和标注工具栏定位固定为“上方优先”：只要选区上方容得下就始终显示在上方；仅在上方不足且下方完整容得下、同时不与对话条相交时放到下方。对话条收纳、展开和透明度动画不得参与工具栏上下方选择。
- 对话条因鼠标进入截图区域而开始收纳后，命中判断必须忽略对话条收纳前的旧占位矩形，直到鼠标真正离开截图区域；否则旧矩形会让对话条反复出现和消失。
- 原位标注的当前颜色必须统一作用于画笔、高亮笔、矩形、椭圆、箭头、文字和实心序号；RGB 自定义色使用 Windows 原生完整颜色选择器。文本框枚举本机系统字体并支持字号和荧光底色；序号按区域从 1 自动递增；椭圆按 Shift 约束为不越过选区边界的正圆。文字和序号必须进入截图快照、导出以及标注模式内的撤销/重做链。
- 多个截图对象同时存在时，鼠标悬浮到哪个显式对象就激活哪个对象并显示其工具栏；重叠区域按视觉层级选择最上层对象，隐式全屏区域不得参与悬浮切换。
- 发送目标必须先按输入来源归一化：只保留用户显式选择的截图/录屏和上传附件，绝不因只输入文字而创建隐式全屏占位；无视觉附件时走纯文字请求，Hermes 仍沿用同一 Profile 的持续上下文。上传文件仍按实际发送顺序加入引用清单，且没有覆盖层选区的文件批注只能安全丢弃，不能映射到别的截图。
- 截图区域不显示视觉数字序号；内部仍保留稳定句柄、附件顺序和 `@图片N` 引用所需的映射，不能为了隐藏标签而删除这些内部绑定。
- 产品不提供独立文字问答窗口；文字 AI 只能在截图覆盖层内工作，允许无视觉附件的纯文字轮次。
- 独立文字问答已移除，不得恢复主界面或托盘中的“快速提问/文字问答”按钮；覆盖层回答仍可使用同一套 Markdown 渲染。
- 对话条显隐动画必须从当前有效位移和透明度继续，恢复时以约 230ms 从屏幕下方向上做线性滑入并渐显；首次唤醒也必须先在屏幕外完成布局再播放同一入场动画。动画期间的 `SizeChanged`、悬浮对象切换和定位钳制只能移动宿主，严禁取消显隐动画或直接写入可见终态；动画使用 `FillBehavior.Stop` 且目标值写入基础属性，避免 `HoldEnd` 残留导致闪现。
- 对话条回答区的最大高度必须按显示器可用高度计算，不能把当前 `DesiredSize` 再反馈成下一轮上限，否则多次测量会把回答区越压越小。回答展开时输入区底边保持锚定，内容只向上扩展。
- 屏幕结构化回答必须兼容完整 JSON 代码块及 ` ```json{...}` 同行围栏，但最终 UI 只能显示根 `answer`，不得泄漏围栏、协议字段或原始批注 JSON。
- 屏幕请求明确要求结构化回答时，疑似 JSON/JSON 围栏却缺少字符串根 `answer`、根类型错误或内容损坏且无法安全恢复，应按无有效正文失败处理，严禁把原始协议 JSON 当成普通回答显示；MiniMax M3 请求需显式使用 `reasoning_split=true` 与 `thinking.adaptive`，首个思考增量必须立即展开显示，不能等待正文到达。
- 退出手动标注时为提交文字框可以先清理键盘焦点，但必须立即把焦点恢复到可聚焦的覆盖层根画布；同时按 `IsMouseCaptureWithin` 释放 InkCanvas 子树捕获。否则完成任意标注后后续 Esc 可能没有路由目标，形状绘制中断时也可能让覆盖层表现为卡死。
- Hermes 的“Agent / 人格”选择必须使用网关 `profiles.list` 返回的真实 Profile；模型枚举、会话创建/恢复和 TTS 都要携带同一 `profile`。不同 Profile 各自保留独立持续会话，严禁为了切人格写 `SOUL.md`、切换 Hermes 全局默认 Profile 或重启用户现有网关。
- 截图覆盖层与其视觉附件引用中的 AI 正文统一渲染为原生 WPF `FlowDocument` Markdown，并保持文字可选择、可复制。Markdown HTML 只能按普通文字显示，远程图片不得自动加载，链接只允许用户主动打开 `http/https`；emoji 必须经 Emoji.Wpf 转成 Segoe UI Emoji 的彩色矢量层，不能退化成 WPF 默认黑白字形，复制时仍须还原原 Unicode；流式回答必须节流，不能每个 token 都重建文档。
- 覆盖层撤销/重做按鼠标所在区域分流：鼠标位于显式截图区域时，`Ctrl+Z`、`Ctrl+Shift+Z`/`Ctrl+Y` 操作截图历史，即使输入框仍保有键盘焦点；只有鼠标位于底部对话条且可编辑输入框有焦点时，才交给 WPF 文本框自身处理文字撤销/重做。OCR、翻译、AI 识图、区域新建/删除/移动/缩放都必须进入有限截图历史，撤销期间不得提前释放可重做区域持有的视频或 OCR 资源。
- 截图覆盖层的 AI 请求失败必须写入 `PrivacyLogger`，并按 Provider 请求阶段与回答渲染阶段区分组件名；日志只记录脱敏异常，不得记录 prompt、answer 或附件内容。OCR/翻译异常同样必须落脱敏日志。
- 贴图窗口双击必须直接关闭贴图（不是只把 `Topmost` 改为 `false`）；贴视频仍按既有产品行为取消置顶。单击按下时不得立即调用 `DragMove` 打断双击计数，只有鼠标移动超过 WPF 系统拖动阈值后，才按 `PointToScreen` 的物理像素增量用 `SetWindowPos` 移动，保持多屏与混合 DPI 正确。右键菜单的“置顶/取消置顶”文字必须与实际 `Topmost` 状态同步。
- 上传图片的引用标签与 `@` 候选项可作为 WPF 原生拖放源；拖到透明覆盖层后应按落点所在显示器的物理工作区生成贴图，保持比例并限制初始尺寸。贴图注册后必须刷新冻结桌面把受防捕获保护的贴图合成进截图背景，同时把真实贴图 HWND 明确保持在截图覆盖层上方，便于直接拖动和双击关闭；从贴图外开始的框选仍可通过冻结背景再次截取贴图。文本和视频附件不得伪装成图片贴图。
- AI 视频时间轴批注必须留在原录屏选区：单点事件 seek 到目标时刻、暂停并显示框；动作过程从起点播放到终点，按当前帧时间在关键帧间线性插值跟踪框并在终点自动暂停。新请求、手工播放、删除区域、撤销重做和关闭覆盖层都必须取消旧的区间控制并拒绝迟到帧更新。
- 流式思考区每次渲染增量及最终内容替换后都必须滚动到底部；空正文或请求异常不得回滚并抹掉已经显示的思考/回答层，应停止思考动画、保留可展开的思考内容并显示明确失败卡，同时禁止写入历史和批注。
- 视频理解提示应默认要求关键事件/可定位目标的时间轴批注；解析允许首尾关键帧位于区间端点以内，不要求严格等于 `startTime/endTime`。模型未返回有效视频批注时必须明确提示“没有时间轴标注”，不能显示完整成功。
- 所有首轮视频回答都应在同一请求所有权和附件租约内做至多一次独立完整性核验，不能只在批注数为零时补标；核验需覆盖原问题中的每个独立对象/片段并校正为目标稳定出现的时间，只有有效批注数不少于初稿时才替换。成功批注需在 Markdown 回答末尾生成本地可点击“跳到/播放”链接，链接直接驱动原位视频 seek 或区间跟踪，不得伪装成外部 URL、打开浏览器或新窗口。撤销重做恢复回答时也要按快照批注重建链接。
- 有效视频批注落地后按全部关键帧的最早时间自动跳转、暂停并渲染第一处标记；多个独立固定事件分别生成跳转链接，单个动作区间只生成一条“播放区间”链接，不能再把起点和终点伪装成两个重复事件。跳转链接只 seek 后暂停，播放链接才启动区间跟踪。
- 视频初稿的批注映射与画布应用必须先于完整性核验：初稿一到立即原位画框、跳到首标记并生成链接。核验应先在内存中映射，只有有效批注数不少于初稿才整体替换；核验取消、异常或较差结果必须保留初稿。单视频可容错重映射错误 `regionIndex`，多附件不得放宽。
- 保存截图或录屏时仅在确有 AI/手工标注时询问是否包含标注；选择“否”必须重新从干净截图帧或源 MP4 导出，不能复用默认带手绘的预览图。录屏对象同样允许进入原位绘图模式，手工层作为全时段静态覆盖，AI 层按批注时间动态合成。
- 覆盖层的保存选择与 RGB 调色使用自有圆角模态窗，不能露出 Windows/WinForms 默认控件风格；模态窗必须是覆盖层的 owned window、启用防捕获并保持当前标注会话。字体下拉从 WPF `FamilyNames` 选取当前中文语言名称，内部仍使用字体 `Source`。颜色选择修改文字前景色，荧光底色固定为黄色且与文字颜色互不覆盖。
- 回答中的视频动作以 `BlockUIContainer` 内的圆角按钮气泡呈现；同一正文再次设置动作时必须从 Markdown 原文重建整个文档，禁止向旧文档追加导致重复和陈旧回调。每个按钮事件显式捕获当前动作副本，确保第二个及后续定位能独立 seek。
- 覆盖层 AI 控件按后端能力分别显隐：无可用对话后端时整个 `PromptBarHost` 与区域引用按钮保持折叠；原位翻译只在远程 Provider 配置和凭据可用时显示，不能因为仅有 Hermes 而露出不可用的翻译按钮。
- 翻译图层在复制、贴图和带标注图片保存时必须按区域物理像素扁平化，且位于手工标注之上、AI 标注之下；选择保存干净原件时必须排除译文。
- 自动框选预览位于选区层之上但不得命中鼠标；单击接受预选窗口，拖动越过系统阈值则进入普通框选。句柄吸附只改变对应边，不能跳动对边或生成小于最小尺寸的区域。
- 智能句柄吸附的 UI Automation 探测必须保持单个有界在途任务，鼠标移动只更新待探测坐标，不能在每个 MouseMove 中取消并重启探测；探测完成后再处理最新坐标，旧预览必须先隐藏，避免持续移动时吸附永远没有结果。
- 句柄吸附实现采用两阶段命中：Win32 `WindowFromPoint`/有序窗口枚举先给出即时预选，随后只对当前窗口做 `AutomationElement.FromPoint` 父链和单分支空间遍历；禁止恢复全窗口 UIA 深度扫描。预选和精确目标使用短期有界缓存，按下时必须同步完成一次精确探测后再锁定，避免移动到按钮时仍误选整个窗口。
- 截图吸附不能因 Chromium/Electron 的原生渲染宿主 HWND 略小于根窗口就跳过 UIA 单分支复核；无论快速命中根窗口还是宿主子 HWND，最终都必须从该窗口根做一次有界 UIA 分支命中，优先返回真实 Button/Edit/MenuItem 等控件边界。
- 贴图旋转后应围绕当前内容重算窗口尺寸并保持长宽比，超高的长截图按工作区高度缩小宽度而非纵向压扁；右键复制和保存始终使用当前旋转方向。
- 多附件识图不能把界面显示的 `@图片N` / `@视频N` 直接当作 `regionIndex`：每个选区需持有不可变 `referenceHandle`，请求清单显式绑定显示标签、实际附件顺序、句柄、像素尺寸和归一化四角坐标。模型批注同时返回序号与句柄；句柄优先纠正冲突序号，未知句柄必须拒绝，不能回退后把框画到别的附件。输入框键入 `@` 应列出当前显式图片和视频，并把选择绑定到实际选区对象。
- 截图覆盖层的实时取色必须直接读取冻结桌面的物理像素，显示 `#RRGGBB` 色值、颜色预览和虚拟桌面物理坐标；多屏左侧/上方显示器允许负坐标。提示卡跟随指针并在四边做有限翻转和钳制，不能超出覆盖层，也不能进入截图导出内容。
- Provider 设置中的 Model 保持可编辑，同时允许从标准火山方舟 `/models` 接口拉取当前账户的对话/理解模型；列表过滤嵌入、图片生成、视频生成和 3D 模型，保留手输 ID 以兼容灰度发布。模型能力必须决定视觉附件是否可发送，纯文本模型仍可用于覆盖层文字对话，但不能被当成视觉模型。
- AI 图片批注框在渲染前使用干净截图做保守的本地边缘贴合；只有同一轴两侧都存在高置信强边缘、候选显著强于模型原边界且新尺寸接近模型粗框时才修正，视频动态框不做静态贴边。`callout.geometry.rect` 始终是目标框，客户端只画一条红色目标框；气泡是独立布局，必须优先放在不覆盖目标的左右/上下空位，并可在所属选区内有界拖动，连线与端点必须实时跟随。与 callout 重叠的 rectangle/ellipse 必须去重，不能再出现偏移的蓝色重复框。
- AI 图片批注先以模型粗框中心命中下层窗口的 UI Automation 元素；命中到可用原生控件时，必须直接换算其真实物理边界并跳过图像贴边，从而与 computer-use 的 accessibility-first 定位一致。控件外的图片、画布或 UIA 不可用时，才保留图像边缘微调；每轮最多处理 12 个候选，避免阻塞覆盖层。
- 图片与视频 AI 标注统一使用版本化 `mewu.visual-annotations/1` 协议，以不可变 `referenceHandle` 和完整附件 `regionIndex` 绑定目标，空间统一为附件内 0–1 坐标，视频额外使用秒级时间轴关键帧。同一协议支持 callout、画笔、高亮、矩形、椭圆、箭头、文字、序号和马赛克；旧扁平框协议只作为读取兼容，新请求不得继续生成旧协议。
- 对话条顶部提供“提问与历史 / Prompt & history”抽屉，默认折叠；展开时必须在同一覆盖层内向上增长，显示当前提问和最近的完整用户—AI 对话，并限制条数与单条文本长度，不能遮挡输入区或破坏回答区滚动。请求尚未返回回答时也必须能查看本次提问；撤销/重做快照需同步恢复当前提问，Esc 和全局快捷键仍由覆盖层优先处理。
- 覆盖层重建时应从本机 JSONL 历史有界加载当前 Provider/Profile 的完整问答；同一 AppHost 生命周期内即使关闭磁盘历史开关也保留内存会话，重新唤醒仍可查看本轮记录。损坏行逐条跳过，不得让整个历史面板变空，也不得把其他 Provider/Profile 的问答混入发送上下文。
